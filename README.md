# Python Host PRO

نسخهٔ ارتقایافتهٔ پروژهٔ Python Host ارسالی. ربات تلگرام می‌تواند پروژه‌های Python (`.py` یا `.zip`) و Node.js (`.zip` دارای `package.json`) را دریافت کند و هر پروژه را در یک کانتینر Docker جدا اجرا کند.

## امکانات این نسخه

- آپلود فایل Python یا ZIP پروژه
- پشتیبانی از پروژه Python با `main.py`، `app.py` یا `bot.py` و نصب وابستگی‌ها از `requirements.txt`
- پشتیبانی اولیه از Node.js با `package.json` و اسکریپت `start` یا فیلد `main`
- اجرای جداگانهٔ هر پروژه در کانتینر Docker
- محدودیت پیش‌فرض هر کانتینر: RAM برابر ۲۵۶ مگابایت، CPU برابر ۰٫۵ هسته و ۶۴ پردازه
- توقف، اجرای مجدد، مشاهدهٔ ۴۰ خط آخر لاگ و حذف پروژه
- ذخیرهٔ دائمی کاربران، ادمین‌ها، مسدودیت‌ها و پروژه‌ها در SQLite با WAL؛ دیتابیس هنگام راه‌اندازی پاک نمی‌شود
- دستورات مدیریتی: آمار، مسدود/آزادکردن کاربر، افزودن ادمین و مدیریت کانال اشتراک اجباری
- اعتبارسنجی مسیرهای ZIP و سقف حجم آپلود و تعداد پروژه‌ها

## محدودیت‌ها و هشدارهای امنیتی

1. اجرای کد ناشناس هیچ‌وقت کاملاً بی‌خطر نیست. این نسخه از کانتینرهای بدون دسترسی privileged، بدون capability اضافی، با `no-new-privileges`، فایل‌سیستم فقط‌خواندنی و محدودیت منابع استفاده می‌کند؛ با این حال برای میزبانی عمومی و تجاری، بازبینی امنیتی مستقل و سیاست شبکهٔ خروجی لازم است.
2. ربات برای ساخت/اجرای کانتینرها به Docker socket میزبان دسترسی دارد. این دسترسی بسیار قدرتمند است؛ خود ربات و حساب مدیر سرور باید کاملاً محافظت شوند. هرگز Docker socket را به کانتینر پروژه‌های کاربران وصل نکنید.
3. کانتینرهای پروژه در شبکهٔ bridge و با دسترسی خروجی اینترنت اجرا می‌شوند تا ربات‌های تلگرام بتوانند به APIها وصل شوند. قبل از استفادهٔ عمومی، دسترسی کانتینرها به IP متادیتای Google Cloud یعنی `169.254.169.254` را در لایهٔ میزبان مسدود کنید و به VM یک Service Account با حداقل مجوز یا بدون مجوز غیرضروری بدهید.
4. هرگز فایل `.env`، توکن ربات یا کلیدهای Google Cloud را در GitHub آپلود نکنید.
5. نسخهٔ اولیه فقط برای پروژه‌های کوچک است؛ قابلیت‌هایی مانند دامنه/پورت اختصاصی، پرداخت آنلاین، صف ساخت، مانیتورینگ کامل و اجرای چندسروری هنوز پیاده نشده‌اند.

## ۱) آماده‌سازی توکن

توکنی که در فایل قبلی قرار داشت افشا شده است. آن را در `@BotFather` باطل/تعویض کنید و فقط توکن جدید را استفاده کنید.

شناسه عددی تلگرام مالک را از رباتی مانند `@userinfobot` بگیرید.

```bash
cp .env.example .env
nano .env
```

مقادیر `TELEGRAM_BOT_TOKEN` و `OWNER_ID` را تنظیم کنید.

## ۲) اجرای محلی یا روی VM

نیازمندی‌ها: Ubuntu 22.04/24.04، Docker Engine و Docker Compose plugin.

```bash
sudo bash deploy/google-cloud-startup.sh
sudo usermod -aG docker "$USER"
# سپس از SSH خارج و دوباره وارد شوید
cp .env.example .env
nano .env
docker compose up -d --build
docker compose logs -f
```

توقف:

```bash
docker compose down
```

داده‌ها در Docker volume با نام `python-host-pro_host_data` باقی می‌مانند. برای حذف کامل داده‌ها باید عمداً volume را نیز حذف کنید؛ این کار برگشت‌پذیر نیست.

## ۳) ساخت VM در Google Cloud

در Google Cloud Console:

1. یک Project انتخاب یا ایجاد کنید و Billing را فعال کنید.
2. Compute Engine API را فعال کنید.
3. به Compute Engine → VM instances → Create instance بروید.
4. برای شروع Ubuntu 22.04 LTS، نوع ماشین کوچک مانند `e2-medium` یا بزرگ‌تر بر اساس تعداد کاربران، دیسک ۲۰ تا ۳۰ گیگابایت و منطقهٔ نزدیک به کاربران را انتخاب کنید. هزینه بر اساس منطقه و مصرف محاسبه می‌شود.
5. برای مدیریت، ترجیحاً از IAP/OS Login استفاده کنید. پورت SSH را به همهٔ اینترنت باز نگذارید.
6. برای ربات تلگرام که polling استفاده می‌کند، نیازی به بازکردن پورت ورودی وب نیست؛ خروجی اینترنت باید فعال باشد.
7. از طریق SSH وصل شوید و مراحل بخش ۲ را انجام دهید.

مستندات رسمی: https://cloud.google.com/compute/docs

## ۴) دستورات ربات

- `/start` منوی اصلی
- `/myid` نمایش شناسه تلگرام
- `/stats` آمار (ادمین)
- `/ban USER_ID [reason]` مسدودکردن کاربر
- `/unban USER_ID` رفع مسدودیت
- `/addadmin USER_ID` افزودن ادمین
- `/channel @channel` افزودن کانال اشتراک اجباری
- `/unchannel @channel` حذف کانال اجباری

ربات باید در کانال اشتراک اجباری ادمین باشد تا بتواند عضویت را بررسی کند.

## ۵) ساختار پروژهٔ کاربر

Python:

```text
my-bot.zip
├── main.py
└── requirements.txt
```

Node.js:

```text
my-app.zip
├── package.json
├── package-lock.json  (اختیاری)
└── index.js
```

فایل‌های محیطی و اسرار را در ZIP کاربران قرار ندهید. در این نسخه امکان واردکردن امن secrets اختصاصی برای هر پروژه هنوز وجود ندارد.

## فایل‌های مهم

- `app/main.py`: کد اصلی ربات مدیریت هاست
- `Dockerfile`: تصویر اجرایی ربات
- `docker-compose.yml`: راه‌اندازی با volume دائمی
- `.env.example`: نمونهٔ تنظیمات محرمانه
- `deploy/google-cloud-startup.sh`: نصب Docker روی Ubuntu

## وضعیت آزمایش

کد از نظر نحو Python بررسی می‌شود؛ برای تست واقعی باید توکن تازه، شناسه مالک، Docker daemon و VM Google Cloud در اختیار باشد. اجرای زنده روی حساب تلگرام یا ساخت VM در حساب Cloud کاربر از داخل این فایل ZIP انجام نمی‌شود.
